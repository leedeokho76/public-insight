1. 추진근거

  • 일일 공공 정책 요약 서비스 거번업(GovernUp) 추진 계획

2. 추진개요

  1. 추진기간: 2026. 1. ~ 2026. 5. (4개월)
  2. 수행인력: 행정전문가(일반행정사) 0.25인 / 초급기술자(정보처리기사) 0.75인
  3. 개발인프라
    • (RPA Machine) Intel Core i3-10105 3.70GHz / RAM 16.0GB / SSD / Windows 11 Pro
    • (DB) SQLite (Public Domain)
    • (Automation Engine) MS Power Automate Cloud(SaaS) & Desktop(On-premises) (free for a limited time)
    • (Web Builder) Hugo Extended (Apache License 2.0)
    • (VCS) Git (GPLv2) & Github.com (Free tier SaaS)
    • (CI/CD) Github Actions
    • (Web Hosting) Cloudflare Pages (Free tier SaaS)
    • (ETC) MS Forms(Free tier SaaS), Daum Smartwork(Free tier SaaS), Puppeteer(Apache License 2.0)
  4. 주요내용: 정부 부처별 보도자료를 신속하게 확보하고, 분야 및 날짜별로 제공하는 웹사이트를 구축하여, 공공정책 정보를 필요로 하는 수요자에게 매일 Email로 제공하는 자동화 서비스 구축

3. 범주화 및 그룹화 결과

3.1. 범주화

  • 일일 루틴을 통해 자료 수집이 수행되고 있어 일 단위 범주화 합리성 충족
  • 디렉터리 구조 또한 연·월로 관리하도록 설계

3.2. 그룹화

  • (중앙행정기관 현황) 2026. 1월 기준 국무총리실과 국가 행정사무를 담당하는 중앙행정기관 총 55개소
    • 국무조정실(국무총리비서실은 정책업무를 수행하지 않아 제외)
    • 총리직속 6개 처
    • 19개 부
    • 18개 외청
    • 독립된 중앙행정기관으로서 7개 위원회
    • 대통령 자문 및 심의 기구로서 4개 위원회
  • (그룹화 기준) 국회법 제37조(상임위원회와 그 소관)
    • 55개 기관이 생산하는 정책 자료의 효율적 제공을 위한 정책적 기준 고려

6. 주요성과 및 시사점

6.1. 총평

  • 본 프로젝트는, 데이터 입·출력·수정·갱신이 중심인 DB 집약적 시스템과 달리, 로컬에서의 데이터 가공 자동화와 온라인에서의 콘텐츠 배포 파이프라인을 중심에 두고 경량화된 구조와 유연한 확장성을 고려하여 설계되었다는데 큰 의의

6.2. 휴먼 인지의 적절한 개입

  • (정책통찰) 정책적·행정적 고려가 필요한 범주화·그룹화 및 위원회·부처 기초자료 수집 등에 행정전문가의 역량을 적절히 투입하여 자료구조의 안정성과 서비스의 효율성을 제고
  • (고객이해) 구독 정보 구축 단계에서는 인지적 개입을 통해 고객의 유효성을 평가하고 이용자 특성을 파악함으로써 맞춤형 응대에 대비

6.3. 효율적 데이터 관리

  • (DBMS전략) 자동화 프로세스를 통한 공공정책 일일브리핑 시범 추진 결과를 토대로 DBMS 도입의 필요성을 인지하여, 가벼우면서도 안정적인 트랜잭션과 표준SQL 및 제약 조건 등 RDBMS의 본질적 장점 지원이라는 요구사항에 부합하는 SQLite롤 채택하게 되어, 서버설치 불필요, 클라우드를 통한 손쉬운 백업, OS 변경시 이식 용이 등 운영 편의성도 증대
  • (최적화) 구독괸련 관심분야와 이메일 정보는, 자원소모가 적고 구조가 유연하며 앱을 통한 접근도 간단한 JSON파일로 운용하되, 향후 CRM 확장시 데이터 관리 적정화 평가를 통해 호스티드 DBMS로 이전 여부를 검토

6.4. 자동화

  • (Local자동화) Power Automate Desktop을 도입하여 콘텐츠 생성 과정을 자동화함으로써, 고비용의 자동화 도구에 의존하지 않고 직관적 운용이 가능한 PC 하드웨어, 운영체제, 브라우저 등 로컬 기반 자원을 효과적으로 활용
  • (CI/CD자동화) 당초 로컬에서 hugo(웹사이트 빌더)를 빌드하고 그 결과물만 웹서버에 업로드하여 배포하는 것으로 계획하였으나, 구축 과정에서 Github Actions의 가용성을 인지하여 CI/CD 플랫폼을 활용하게 되었고, Git Push 이후의 빌드 및 업로드 과정이 자동화되어 배포 편의성 혁신

6.5. 독립적 블록 설계와 확장성 확보

  • (구성) “여러 사람에 의해 운영할 경우"를 가정하고 DB 관리, 웹 스크래핑, 콘텐츠 생성, 빌드, 배포를 각각 독립된 형태로 블록화
  • (자원연결) 서비스 목적 달성을 위해 Cloudflare Pages, Daum Smartwork, MS Forms, Puppeteer 등 서로 다른 기술을 유기적으로 결합
  • (지능화) 새로운 데이터 소스나 배포 채널을 추가하기 용이하며, 장기적으로 AI 파이프라인을 결합해 지능형 자동화로 확장 가능한 구조 마련

7. 향후 계획

  • 정적웹사이트 토대가 마련되어, 실시간 댓글 서비스 확장을 위한 서버리스 및 noSQL DB 등 백엔드 자원 연계 계획 수립 추진
