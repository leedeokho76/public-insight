1. 추진근거 및 배경

  • 퍼블리크 정적웹사이트 전환 계획 (2025-11-19)
  • 퍼블리크 정적웹사이트 전환 결과 (2026-01-01)
  • 블로그 형태의 정적웹사이트 전환과정에서, 다음 세가지 사안을 추후 결정하도록 계획
    • 콘텐츠 페이지와 랜딩페이지의 도메인 (분리)결정 (예: know.public.re.kr)
    • (분리할 경우) 히어로 섹션과 랜딩페이지 디자인
    • 랜딩페이지의 웹 플랫폼 선정

2. 추진개요

  • (추진기간) 2026. 2. 1. ~ 2026. 3. 12. (40일간)
  • (투입인원) 초급기술자(정보처리기사) 0.75인 / 행정전문가(일반행정사) 0.25인
  • (활용자원) pc, vscode 및 github.com 계정
  • (주요내용) 현행 블로그 형태로 구축된 메인페이지를 지식베이스 서비스 insight로 변경하고, 랜딩페이지를 메인페이지로 구축하는 정보 구조 재편 수행
    • Astro 기반 정적 웹사이트 구축
    • hugo 웹사이트 hero 테마 설정

3. 성과 및 시사점

3.1. 주요 성과

  • 택스트 위주의 블로그로 운영되던 메인페이지 대신, 랜딩페이지를 구축하고 루트 도메인에 연결하여 브랜딩과 마케팅 역량을 강화
  • 블로그는 insight라는 명칭으로 브랜딩하고 2차도메인(insight.public.re.kr)에 연결하여 지식콘텐츠 허브로 운영
  • 랜딩페이지 개발·운영에 요구되는 순발력과 높은 자유도를 고려, 웹사이트 빌더로 Astro를 도입함으로써 컴포넌트 중심 개발의 유연성과 확장성을 확보
  • 또한 Node.js 환경을 본격적으로 활용함으로써, 향후 JavaScript 기반 FullStack 역량을 발전시킬 수 있는 계기를 마련

3.2. 랜딩 페이지 구축 도구 선정

  1. 관련 기술 비교 검토

    구분 Hugo Astro
    핵심철학 단순성, 초고속 빌드 컴포넌트 기반, 최소한의 JavaScript
    기반언어 Go lang Node.ja, JavaScript, TypeScript
    빌드속도 동종 빌드 TOP 빠른편
    파일구조 콘텐츠·레이아웃·데이터의
    강한 분리    		 페이지와 컴포넌트 중심

  2. 사전 검증

    (Hugo) Hero-theme 를 이용한 시범 구축 결과, 콘텐츠와 레리아웃이 철저히 분리되어 있어 디자인 변경시 여러 파일 수정이 필요하며, 유동적 레이아웃 관리 및 빈번한 콘텐츠 변경에는 부적정
    (Astro) agency-landing-page-Astrojs 테마를 이용한 시범 구축 결과, 정적 콘텐츠와 Interactive UI가 결합된 형태로 빠른 수정, 상호작용, 디자인 자유도 면에서 우수

  3. 선정결과

    • 구축 플랫폼의 특성 분석 결과, hugo의 경우 안정성과 대량 콘텐츠 처리의 신속성 등에서 블로그에 적합한 반면, Astro의 경우 정적 콘텐츠와 Interactive UI가 결합된 형태로 랜딩·이벤트 페이지에 구성에 적합한 것으로 판단하여 Astro 선정

3.3. 도메인 활용

  1. 보유자원

    public.re.kr
    pub7.kr
    localgov.kr

  2. 블로그를 브랜딩할 경우 도메인 네임 및 저장공간 검토

    • (1안) 현 도메인의 Path 기반 접근

    (Domain) public.re.kr/insight
    (Hosting) 블로그 빌드 결과물을 현 리포지토리의 하위폴더에서 관리

    • (2안) 현 도메인의 SubDomain 기반 접근

    (Domain) insight.public.re.kr
    (Hosting) 블로그 빌드 결과물을 동일 계정 내 별도 리포지토리에서 관리

    • (3안) 다른 도메인 활용

    (Domain) pub7.kr 또는 localgov.kr 활용 (Hosting) 블로그 빌드 결과물을 별도 계정의 리포지토리에서 관리

  3. 선정결과

    • Path 기반 접근시, 각각 다른 빌더를 사용하는 랜딩페이지와 블로그가 동일 Repository에 위치하게 되고, CSS 등 UI 자원을 공유하게 되어 디자인 요소 충돌 및 랜더링 오류 발생 가능
    • 반면 블로그를 지식 콘텐츠 허브로 운영할 계획이지만, 현 규모에서 별도의 도메인을 매칭하여 서비스 할 정도로 규모의 경제와 채산성을 갖추고 있다고 볼 수 없으며, 자원 관리 차원에서도 도메인 할당은 부정적
    • 동일 계정 내 리포지토리 분리를 통해 자원 공유를 원천적으로 차단하여 오류 가능성을 근원적으로 해소하고, 서브도메인 매칭 및 활용을 통해 주력 도메인인 public.re.kr이 랜딩페이지만으로 부실해 질 수 있는 상황 대응
